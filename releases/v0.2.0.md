# gorilla-size 0.2.0 — Gorilla Size Calculation

## For everyone (Layman Track)

**What it is.** One small program, one file, nothing to install. You point it at a folder (or a whole drive) and it
tells you, biggest first, what is inside and how much room each part takes. It is fast: on a normal laptop it weighed
a folder of 3.2 million files in about five seconds, where the usual tool had been stopped after 25 minutes on a
folder of half a million.

**What it can do for you.**
- **Find out where the space went**: the biggest folders and files, the kinds of files that take the most room
  (for example: "all the .iso files together: 40 GB").
- **Find things**: "every file over 2 GB nobody has opened for a year", "every folder over 10 GB", "every log that
  mentions ERROR", and show you the lines you need from them, without opening anything.
- **Find duplicates**: the same file kept in several places, and how much room you would win back.
- **Tidy up safely**: copy, move, or send to the Recycle Bin. Every step is **checked** (a copy is compared byte by
  byte with the original; something sent to the Recycle Bin is looked for in the Recycle Bin afterwards) and every
  step can be **undone** with one command.
- **Compare**: measure today, measure next week, and see what grew.

**Two promises.**
1. **It never deletes anything for good.** The Recycle Bin is as far as it goes, and emptying the bin stays your
   decision. It even refuses to recycle something when Windows would secretly destroy it instead (that happens when
   the bin is too small, on USB sticks, or with very long folder paths).
2. **It never connects to the internet.** No updates, no data sent anywhere.

**Big jobs wait for you.** Moving or recycling more than 1,000 files or 10 GB at once is not done straight away: the
program writes down exactly what it would do and waits until you have looked at the list and said go.

**How to start.** Download the file for your computer below, put it in a folder, and run it in a terminal:
`gorilla-size C:\Users\you\Documents` (Windows) or `gorilla-size ~/Documents` (Linux). `gorilla-size --help` lists
everything.

## For developers and auditors (Developer Track)

**Build.** Rust, edition 2021, one static binary: Windows x86_64 with the C runtime linked in (2.6 MiB), Linux
x86_64 musl. Built in CI from `vendor/` only (`--offline --locked`); 15 crates are compiled in (rayon and crossbeam;
serde_json and its helpers; regex, regex-automata, regex-syntax, aho-corasick), each listed with its reason in
`DEPENDENCIES.md`. SHA-256, gitignore matching, globs, the Recycle Bin/trash code, the NTFS master file table reader
and every Windows API declaration are written in this repository.

**Since 0.1.0.**
- Measure: `types` (bytes by extension), `--reverse`, `--flat`, `--long`, `--gitignore`, `--exclude`, `--no-hidden`
  (what was skipped is always counted), `--progress`, `newest`/`oldest`, `watch`, `free`.
- Find: `--regex`; output for the next step: `--paths`, `-0`, `--jsonl`, `--format`; read inside matches: `--head`,
  `--tail` (reads only the end of a file), `--lines A:B`, `--grep`, `--grep-re`, byte-capped, binary files recognized.
- `hash` (SHA-256), `dupes` (size, then the first 64 KiB, then the full hash), `empty`, `reparse`.
- Actions: `copy` (every byte compared), `move` (rename, or verified copy + recycle), `recycle`, `undo JOURNAL`,
  plans above 1,000 files / 10 GiB with `apply` (skips anything changed since the plan).
- `recycle` on Windows never calls `SHFileOperation`: it writes the `$I` record (version 2) and renames the item into
  `$Recycle.Bin\<SID>\` as `$R`, which cannot destroy anything; Explorer lists and restores such items like its own.
  Measured why: with `FOF_ALLOWUNDO` that call deleted permanently instead of recycling, after every pre-check had
  passed, once on a laptop (a 4.4 GiB folder) and three times on GitHub's `windows-latest` runner (test folders).
  Refused before acting when the account has no bin folder on that drive, NukeOnDelete is set, the item is bigger
  than the bin, the bin would purge older items to make room, or a path exceeds 259 characters. Linux: freedesktop
  trash.
- Machine profile: CPU (performance/efficiency cores, instruction sets), RAM, disk kind; `profile --recalibrate`
  measures 1..N threads per disk, alternating, and keeps the fastest.
- Hard links: when they are checked (Linux always; Windows with `--links` or `--mft`) a file with several names is
  one file; the extra names are reported as `hardlink_repeats`.
- JSON reports, plans and journals saved with a UTF-8 byte-order mark (Windows PowerShell 5.1) are read.

**Measured (Windows 11, i7-1255U 2P+8E, NVMe, warm cache, medians of alternating runs).**
- 473,152 files: 0.62 s; 956,014 files: 1.23 s; 3.2 million files: 6.0 s. 0.2.0 runs at 0.99-1.03x the speed of
  0.1.0 with all the new functions. Two speed ideas were measured and dropped: `FIND_FIRST_EX_LARGE_FETCH` was about
  30 % slower than plain listing; building paths for every entry cost time and is now done only when needed.
- Threads on that NVMe drive: 1 = 7.6 s, 4 = 2.6 s, 8-12 = 1.4 s (equal within noise).
- `--mft` against the walk: identical bytes and files on 473,152 and 956,014 files. On 3.2 million files the bytes
  differed only where a build was writing during the run; the file count differed by the hard-linked names the walk
  then counted as files (2,857 names, 2,855 files): fixed in this release. The master file table is read whole
  (about 15 s on that drive), so `--mft` wins on whole drives, cold caches and hard-link counting, not on one folder
  with a warm cache.

**Doors.** No network code. Changes only what `copy`, `move`, `recycle`, `undo` and `apply` are asked to change.
No permanent delete. Journals: `%LOCALAPPDATA%\gorilla\journal` / `~/.local/state/gorilla/journal`; plans next to
them; the machine profile in `machine.json` there. Nothing leaves the machine.

**Verify the download.** `SHA256SUMS` is attached; compare it with `gorilla-size hash <file>` or `certutil -hashfile
<file> SHA256` / `sha256sum <file>`.

**Tests.** 30 unit tests and 27 integration tests on Windows and Linux CI, including a real round trip through the
Recycle Bin (checked through Explorer's own view of the bin on the development laptop), the refusal on a
280-character path, plans, undo, hard links and byte-order marks. The master file table test (the MFT against the
walk, file by file) runs in CI on GitHub's administrator Windows runner.
