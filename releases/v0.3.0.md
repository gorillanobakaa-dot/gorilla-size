# gorilla-size 0.3.0 — Gorilla Size Calculation

## For everyone (Layman Track)

**What it is.** One small program, one file, nothing to install. You point it at a folder (or a whole drive) and it
tells you, biggest first, what is inside and how much room each part takes. This release adds a second small
program, `gorilla-trash`, for the one job `gorilla-size` will never do: emptying the Recycle Bin.

**What is new for you.**
- **See what is in the Recycle Bin, and put things back.** `gorilla-size trash list` shows what is in the bin (where
  it came from, how big, when), newest first. `gorilla-size trash restore NAME` puts an item back where it was.
- **Empty the bin, when you decide to.** `gorilla-trash empty` shows what is in the bin and asks you once
  (`[y/N]`). Only after your yes does it delete exactly those items for good. Anything that landed in the bin after
  the question is left alone. If there is nobody to answer (a script, an AI assistant), it refuses unless it is told
  the exact number of items in the bin.
- **Undo is safer.** If you moved a file away and something new has since been saved under its old name, undo no
  longer overwrites the new file. It refuses and says why. A copy you edited after making it is not thrown away by
  undo either.
- **Compare as a tree.** `compare --tree` shows what grew or shrank between two measurements in the shape of your
  folders, so you can see where in the tree the change happened.
- **Get warned when a folder grows.** `watch --alert-growth 5GB` keeps measuring and stops with a warning the first
  time the folder grows by more than that between two checks.
- **See who owns each file.** `--long` now shows the owner, which explains most "unreadable" lines without another
  tool.
- **Huge files do not eat memory.** Reading inside a 64 MB file with no line breaks now uses a few megabytes, not the
  whole file. Pictures, programs and archives found by a search are described in one line (size, kind) instead of
  being skipped silently.
- **Faster checksums.** On most PCs from the last ten years, checksums (and the duplicate finder that uses them) run
  about seven times faster.

**Two promises, unchanged.**
1. **`gorilla-size` never deletes anything for good.** The Recycle Bin is as far as it goes. Deleting for good is
   only done by `gorilla-trash`, a separate program, after it has shown you the list and you said yes.
2. **Neither program connects to the internet.** No updates, no data sent anywhere.

**One thing that changed in how it answers.** When `dupes` finds duplicates or `empty` finds empty folders, the
program now ends with the code 3 ("found something") instead of 0. That only matters if you call it from your own
scripts.

**How to start.** Download the file for your computer below, put it in a folder, and run it in a terminal:
`gorilla-size C:\Users\you\Documents` (Windows) or `gorilla-size ~/Documents` (Linux). `gorilla-size --help` lists
everything; `gorilla-trash --help` explains the bin program.

## For developers and auditors (Developer Track)

**Build.** Rust, edition 2021, static binaries: Windows x86_64 with the C runtime linked in, Linux x86_64 musl
(static-pie). Four assets: `gorilla-size` and `gorilla-trash` for each OS, plus `SHA256SUMS`. Built in CI from
`vendor/` only (`--offline --locked`) after the tests pass on Windows and Linux for the tagged commit. **0.3.0 added
no crate**: the same 15 crates as 0.2.0, each listed with its reason in `DEPENDENCIES.md`. BLAKE3 (plan item 13)
would need one and is not in this release.

**Since 0.2.0.**
- `trash list` / `trash restore NAME`: the Recycle Bin (`$I` records) and the freedesktop trash (`.trashinfo`) read
  from their own records; records whose item is gone are listed apart and never counted (Explorer hides them).
- `gorilla-trash` (new binary, shared code moved into a library crate): `empty` lists the bin, asks once at a
  terminal and deletes exactly the items it showed, on every core. Without a terminal it refuses unless
  `--confirm N` equals the item count now. Links inside items are removed as links; a test proves the target
  survives. This is the only permanent delete in the project, and it lives outside `gorilla-size` on purpose.
- `recycle`: the 259-character limit is measured at the path inside the bin (where Explorer empties and restores),
  not at the old place.
- `undo` never overwrites: a moved item or an aside goes back only to a free original path (`MoveFileExW` without
  `MOVEFILE_REPLACE_EXISTING` on Windows, checked first on Unix; `std::fs::rename` replaces silently on both). A copy
  edited since the copy is not recycled; a half-made copy is journalled as partial and undone.
- SHA-256: SHA-NI block function chosen at run time (`is_x86_feature_detected!` sha/sse2/ssse3/sse4.1), portable
  fallback; `hash --json` and `profile` name the path (`sha256_impl: sha-ni|portable`). `std::arch` only.
- `bench --profile`: the calibrated thread count (or `-j N`) against every core on the same folder, alternating,
  warm-up each; median, middle half and min/max per side; a winner only when the middle halves do not overlap,
  else INCONCLUSIVE. No calibration for the disk and no `-j`: exit 2, never a silent "every core vs every core".
  `bench` default rounds 3 -> 10.
- `watch --alert-growth SIZE`: ALERT line / `"alert": true` and exit 3 at the first interval that grows more than
  SIZE (shrinking never alerts). Fix: `watch` used to parse and silently ignore `--exclude`, `--gitignore` and
  `--no-hidden`; it now skips like a measurement and reports `excluded` / `hidden_skipped`. A missing PATH is exit 2.
- `compare --tree`: the diff merged from the two reports' own trees (only what changed and the folders on the way),
  `-n` per folder, `--ascii` honored; `--json` gives `{roots: [{name, before, after, delta, change, children}]}`.
  The flat compare is unchanged.
- `find --format`: one pass over the template; a value already inserted is never searched for placeholders again
  (a file named `{bytes}.txt` prints as itself).
- `find` reading: lines are capped in memory at `--max-bytes` (16 KiB default) and the rest streamed past, with
  "truncated at N bytes" said. Binary files summarized: size, kind from magic bytes (PE/MZ, ELF, PNG, JPEG, GIF,
  ZIP, GZIP, PDF, SQLite), first 16 bytes in hex. `find --hash`: SHA-256 per listed file, after grep, sort and `-n`.
- `--long` shows the owner: Windows `DOMAIN\name` (`GetSecurityInfo` on a handle opened with
  `FILE_FLAG_OPEN_REPARSE_POINT`, so a junction shows its own owner; `LookupAccountSidW`, cached per SID, the SID
  string when unresolved), Linux/macOS from `/etc/passwd` (parsed, no libc crate), else the uid.
- `--help` names every option the parser takes; a test holds the two together.

**Behavior changes (callers).**
- Exit codes: 0 ok, 2 usage, 3 findings, 4 refused for safety. `dupes` and `empty` exit **3** when they find
  something (was 0); `reparse` exits 3 only for a broken link. A missing PATH for `hash`, `dupes`, `empty`,
  `reparse` is exit 2 (it looked like a clean result).
- Under `--json` every error is one object on stdout, `{"error": "...", "exit": n}`, parser errors included.
- `--grep` / `--grep-re` now **select**: only text files with a hit stay. `--grep` searches at most `--max-bytes`
  of any single line. Both together is a usage error.

**Measured (Windows 11, i7-1255U, release build).** SHA-256 on 256 MiB in memory, best of 3: portable 143 MiB/s,
SHA-NI 1,047 MiB/s (7.3x), same digest. `find --head 1` / `--grep` / `--tail 1` on a 64 MiB file with no newline:
child peak private memory under 32 MiB (asserted in the tests on Windows and Linux).

**Doors.** No network code. One door noted: `--long` calls `LookupAccountSidW`, which may ask a domain controller
for a domain account's SID; local and well-known accounts resolve locally, and only `--long` calls it.
`gorilla-size` changes only what `copy`, `move`, `recycle`, `undo`, `apply` and `trash restore` are asked to change,
and has no permanent delete. `gorilla-trash empty` deletes permanently, only the items it listed, only after a yes
at a terminal or `--confirm N` equal to the item count. Journals, plans and `machine.json` as in 0.2.0. Nothing
leaves the machine.

**Verify the download.** `SHA256SUMS` is attached; compare it with `gorilla-size hash <file>` or `certutil -hashfile
<file> SHA256` / `sha256sum <file>`.

**Tests.** 35 unit tests and 48 integration tests (83), run on Windows and Linux CI. New in 0.3.0: SHA-256 against
the NIST vectors through both paths, the 64 MiB memory cap, exit codes and JSON errors, undo refusing to overwrite,
`watch` alerts and skips, `compare --tree`, the owner column, a real trash round trip, and the help text against the
parser. Most new tests were checked by putting the bug back and watching them fail. Two tests run only by hand: the
master file table against the walk (administrator) and the 256 MiB SHA-256 speed test.
